# UUID移行の詳細手順

このドキュメントでは、データベースのIDフィールドをIntからUUIDに安全に移行する手順を説明します。

## 必要な準備

1. **依存パッケージのインストール**:
   ```bash
   npm install uuid
   ```

2. **環境のバックアップ**:
   - データベースの完全バックアップを作成
   - 現在のPrismaスキーマをバックアップ

## 移行手順

### ステップ1: 現在のデータをエクスポート

1. 現在のスキーマを使用して、既存のデータをエクスポートします。

   ```bash
   # スキーマをバックアップ（すでにUUIDに変更していた場合）
   cp prisma/schema.prisma prisma/schema.prisma.new
   
   # 古いスキーマを一時的に復元（Int IDを使用するスキーマ）
   cp prisma/schema.prisma.backup prisma/schema.prisma
   
   # データエクスポートスクリプトを実行
   node scripts/export-data.js
   
   # 新しいスキーマを戻す
   cp prisma/schema.prisma.new prisma/schema.prisma
   ```

### ステップ2: 新しいデータベース環境を準備

1. 必要に応じて新しいデータベースを作成するか、既存のデータベースをリセットします：

   ```bash
   # 既存のデータベースをリセットする場合
   npx prisma migrate reset --force
   
   # 新しいスキーマ（UUID）でマイグレーション実行
   npx prisma migrate dev --name uuid_migration
   ```

### ステップ3: 新しいUUIDスキーマに基づいてデータベースをマイグレーション

1. マイグレーションを実行して新しいデータベース構造を作成します：

   ```bash
   npx prisma migrate dev --name uuid_migration
   ```

   このステップが完了すると、新しいUUIDベースのテーブルがデータベースに作成されます。

### ステップ4: 変換されたデータをインポート

1. インポートスクリプトを実行して、変換されたデータを新しいデータベースに挿入します：

   ```bash
   node scripts/import-data.js
   ```

### ステップ5: 検証

1. インポートされたデータが正しいことを確認します：

   ```bash
   npx prisma studio
   ```

   Prisma Studioを開いて、データがすべて正しくインポートされているか確認します。

2. アプリケーションを起動して、すべてが正常に機能するか確認します：

   ```bash
   npm run dev
   ```

## トラブルシューティング

### インポート中にエラーが発生した場合

- エラーメッセージを確認してください
- 特定のレコードに問題がある場合は、export-data.jsを修正して特定のレコードを除外または修正できます
- データ変換ロジックに問題がある場合は、修正してからエクスポート・インポートを再実行してください

### リレーションシップのエラー

- IDマッピングが正しく適用されていない場合、リレーションシップエラーが発生する可能性があります
- id-mappings.jsonファイルを確認して、すべてのIDが正しくマッピングされていることを確認してください

## 注意事項

- この移行プロセスは開発環境でよくテストしてから本番環境に適用してください
- 大量のデータがある場合は、インポートに時間がかかる可能性があります
- 本番環境への適用は、計画的なダウンタイム中に行うことをお勧めします
